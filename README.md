# Blur Inversion Studio

Multi-frame exposure-blur inversion prototype. Given a set of *blurred* frames and
an explicit, user-stated motion + shutter model, it estimates a sharper latent image
by running a real regularised least-squares solve (preconditioned conjugate
gradients), then re-blurs that estimate through the *same* forward model and shows
the residual as evidence of whether the assumption actually explains the input.

Ground truth is synthetic. It never reaches the solver; it is only used, separately,
to score the result (PSNR / SSIM / per-region error) and that scoring is labelled as
such in the UI.

## Launch the UI

```bash
npm install          # installs ffmpeg-static (used only for MP4 export)
npm start            # serves the studio on http://localhost:5173
```

Then open **http://localhost:5173**. No build step is required (the front end is
plain ES modules served statically).

Other commands:

```bash
npm test             # numerical kernel + layered-motion tests (no browser needed)
npm run layers       # auxiliary CLI for the layered (multi-motion) inversion
npm run build        # regenerate out/*.mp4, comparison PNGs, report.json/report.md
npm run smoke        # headless-browser UI walkthrough; writes screenshots to test-output/
                     # (needs Playwright + system Chromium libs; not required to use the UI)
```

`npm run build` writes the deliverable videos and the metrics report into `out/`
and `report.md`; the same files are downloadable from the UI's **Build deliverable
videos** button.

## How to use it

1. **1 · Blurred clips** — pick a synthetic clip. These are the observations; the
   clean sequence is *not* shown by default and is never used by the solver.
2. **2 · Motion analysis player** — scrub / play the blurred frames. *show clean
   reference* reveals the truth for comparison only, flagged as player-only. The
   blind phase-correlation plot estimates inter-frame motion from the observations;
   blur biases this estimate toward zero, so it is a starting point, not truth.
3. **3 · Motion & shutter assumption** — state the model explicitly:
   - motion kind (constant velocity / shake / arc) and vx, vy,
   - shutter fraction ρ and exposure weighting κ(t) (uniform / centred / ramp),
   - reference frame, regularisation λ (auto from the noise estimate, or manual),
     TV weight, max CG iterations,
   - *compare hypotheses* to run the forward-residual comparison as well.
4. **4 · Inversion result** — tabs:
   - **estimate** — the latent estimate (display gain is cosmetic and never feeds
     the solver or metrics),
   - **data residual** — re-blurred estimate vs input, colour-scaled to 4σ,
   - **data support** — local share of high-frequency energy the assumed kernels
     still pass; this separates measured detail from prior fill,
   - **exposure kernel** — the assumed per-frame kernels and displacements,
   - **hypotheses** — forward RMSE for each motion hypothesis; if the top two are
     within 5% the ambiguity is kept and both are reported rather than one being
     silently chosen,
   - **evaluation\*** — ground-truth scoring (PSNR/SSIM/ringing/per-region std);
     marked as evaluation-only.

When an assumption fails (forward residual far above the noise floor, or the solve
diverging) the failure is reported in the result area and fed back as guidance to
change the motion/shutter model — it is not hidden behind a "looks sharper" image.

## Layered (multi-motion) inversion — graphical entry point

For scenes whose foreground and background move **differently**, a single global
kernel cannot explain the whole frame. The studio includes a genuine layered
inversion reachable from the same player (the primary entry point):

1. Pick one of the **Layered · …** clips in panel **1 · Blurred clips** (they are
   generated by the two-layer alpha-composite forward model).
2. In panel **2 · Motion analysis player**, choose the **blur segment** (start/end
   frame range) fed to the layered solve.
3. Panel **3** reveals the **Layered motion inversion** box. Set the layer count
   (capped at `MAX_LAYERS = 3`), the background/foreground velocity seeds, λ, and
   whether to run a protected velocity re-estimation. Coverage masks default to
   **data-driven** (estimated from the observations); hand masks are never the
   default and are used only in the optional oracle/evaluation path.
4. Click **Invert layered blur →**. The button calls the real `src/layers.js`
   kernel — no fixed or faked images — and the **motion layers** result tab opens
   with: the composite estimate, the closed-loop re-blur and data residual,
   per-layer recovered images, coverage/lock masks, per-layer exposure kernels,
   per-layer **uncertainty** maps, and a side-by-side against the global
   single-motion model with both forward RMSE values.

The global single-motion model remains runnable everywhere as the **one-layer
special configuration** of the same machinery (layer count 1, full-window
coverage), so each layer's contribution and the mutual occlusion are visible in
the same framework.

### Declared boundary approximation

A moving object's boundary can be covered by different layers at different times
during one exposure. The generator supports an `exact` time-sampled composite
(coverage re-evaluated at every shutter sample) and a `frozen` approximation
(coverage fixed at the frame centre while each layer image is still fully
blurred). The inversion uses the **frozen** model because it keeps the per-frame
operator an FFT-friendly linear map; the approximation is explicit, not hidden.
The regression tests confirm the frozen oracle closes the loop to ~zero residual
and that, on an `exact` clip, the frozen model's remaining error concentrates at
the layer boundaries rather than in the interiors.

### Two parameterisations, chosen by forward residual

- **independent** — every layer owns its full exposure operator; a joint stacked
  normal-equation system solves all layer latents at once (the default).
- **shared-bg** — one background kernel explains the frame, then each foreground
  layer is fit only to the residual inside its moving lock region (fewer coupled
  degrees of freedom).

Both are scored by the **same** re-blur RMSE and the lower one is selected; the
UI reports both scores and the margin. Layer count and degrees of freedom are
capped, so noise cannot be fit by endlessly adding local kernels: a layer with
negligible coverage is flagged through its uncertainty map instead of being
filled with invented detail.

## Model

Forward model per frame k, shared by generation and inversion:

```
g_k = crop( S_{d_k}( h_k * x ) )
```

- `x` is the latent on a padded 256×128 canvas (zero-padded, circular convolution),
- `h_k` is the exposure kernel: the path of the global motion, integrated over the
  shutter with weight κ(t), and truncated to shutter fraction ρ,
- `S_{d_k}` is an exact Fourier sub-pixel shift to frame k's position relative to
  the reference,
- `crop` extracts the observed 160×96 window,
- observations are quantised to 8-bit and optionally have Gaussian noise added.

The inversion minimises

```
Σ_k || W_k ( A_k x − g_k ) ||²  +  λ || L x ||²  +  λ_tv · TV(x)
```

where `A_k = S_{d_k} H_k`, `W_k` is an observation-support mask, and `L` is a
high-pass (Laplacian) prior. It is solved by preconditioned CG with a logged
residual history — a real iterative optimisation, not a sharpening filter.

### Layered forward model

With `L` motion layers the observed frame is an alpha composite inside the
imaging model (not "blur the whole frame with several kernels then stitch"):

```
g_k = crop( Σ_l m_{l,k} · S_{d_{l,k}}( h_{l,k} * x_l ) )
```

Each layer `l` has its own latent `x_l`, exposure kernel `h_{l,k}`, trajectory
`d_{l,k}` and coverage mask `m_{l,k}`. The masks are **complementary**: the
background coverage is `1 − m_fg`, so every observed pixel is partitioned between
layers and the layer latents share no null space (overlapping all-ones masks
would let two latents cancel and make the system singular). The joint objective
stacks every layer's normal equations into one SPD system

```
Σ_k Σ_l || W_k m_{l,k} ( A_{l,k} x_l − g_k ) ||²  +  λ Σ_l || L x_l ||²
```

solved by restarted preconditioned CG on the stacked unknown `(x_0 … x_{L−1})`,
with a frequency-diagonal block preconditioner `Σ_k|A_{l,k}|² + λ|L|²`. The CG
uses the pure **linear** normal operator; the data constant is separated into the
right-hand side so the recursive residual stays exact. Re-blurring the recovered
latents through the same layered operator reproduces `g_k`, giving a genuine
closed-loop forward residual per frame.

When background motion is re-estimated, the foreground **lock region moves with
the object along time**: candidate background velocities are scored only on
background-covered pixels (the translated foreground footprint is excluded), and
each foreground velocity is scanned inside its own moving lock region. Layers are
then re-convolved and checked one at a time.

### Layer identifiability and uncertainty

A layer that is rarely observed (low time-averaged coverage) is weakly
identifiable. `layerUncertainty` marks reference pixels whose mean coverage falls
below a threshold; the solver leaves those latents regularised rather than
manufacturing structure, and the UI renders the uncertainty map alongside each
layer. This is the layered analogue of the single-motion support map: unmeasured
detail is reported as uncertain, not drawn.

### Scale / shift ambiguity

The exposure kernel and the latent image share a scale and a position: a wider
kernel looks like a more blurred latent, and a global shift can be absorbed into
both. The constraints used here:

- the latent lives on a fixed padded canvas with a fixed observation crop, so the
  observation coordinate frame is pinned to the reference frame,
- inter-frame displacements `d_k` are taken from the stated motion path relative to
  the reference frame, not estimated freely during the solve,
- the shutter fraction ρ and exposure weighting κ(t) are explicit inputs, so the
  kernel's width is not a free parameter of the inversion,
- λ is fixed (auto from the noise estimate or manual), so the prior strength does
  not silently trade against kernel width.

### Data-supported vs prior-filled

`ρ(f) = Σ_k |A_k(f)|² / (Σ_k |A_k(f)|² + λ|L(f)|²)` is the frequency-domain
reliability of each mode. The support map averages this over local windows of the
estimate's high-frequency energy. Values near 1 mean the observations constrain
those frequencies; low values mean the prior is choosing. It uses only the
observations, the assumed operators and λ — no truth.

Fine texture beyond the kernel cutoff is **not** recovered. The evaluation tab
reports `est std / truth std` per region: if that ratio is well below 1 in the
fine-texture patch, the sharpness you see there is prior fill, not measured detail.
The UI says this explicitly rather than treating extra local contrast as success.

## Results

`npm run build` produces `out/report.md` and `out/report.json`, plus a labelled
four-panel MP4 per case (clean sequence / blurred input / inverted estimate /
forward residual) and still comparison sheets. Example (synthetic, 7 frames):

| clip | blur PSNR | estimate PSNR | gain | SSIM | forward RMSE | fwd/σ | ringing |
|---|---|---|---|---|---|---|---|
| pan-clean | 28.6 | 40.5 | +11.9 dB | 0.965 | 0.0008 | 0.92 | 1.9 |
| diag | 27.5 | 39.4 | +11.9 dB | 0.922 | 0.0030 | 0.96 | 2.5 |
| fast | 24.6 | 32.3 | +7.8 dB | 0.806 | 0.0033 | 1.12 | 8.5 |
| noisy (σ 0.012) | 27.4 | 31.0 | +3.6 dB | 0.736 | 0.0116 | 1.06 | 11.7 |

`fwd/σ ≈ 1` means the re-blurred estimate explains the input down to the noise
floor; a reversed or stationary kernel gives 25–46× larger forward residuals and is
rejected by the same test.

### Layered results (synthetic, 5 frames, ρ = 0.8)

Forward RMSE and composite PSNR for the layered model vs the global single-motion
special configuration. The oracle row uses truth coverage (evaluation only) to
isolate inversion quality; the data-driven rows derive masks from the observations.

| scenario | masks | layered RMSE | single RMSE | residual reduction | layered PSNR |
|---|---|---|---|---|---|
| opposed fg/bg (frozen) | oracle truth | 0.0020 | 0.0525 | 96.1% | 38.1 dB |
| moving fg, static bg | data-driven | 0.0223 | 0.0610 | 63.5% | 27.6 dB |
| opposed fg/bg (frozen) | data-driven | ~0.05 | ~0.053 | segmentation-limited | uncertainty flagged |
| exact time-sampled edges | data-driven | boundary-localised | — | frozen approximation error at edges | — |

The frozen-boundary oracle closes the forward loop to RMSE ≈ 2e-3 (PSNR ≈ 38 dB),
showing the layered inversion itself is correct; the gap on blind clips is driven
by coverage estimation, which the per-layer uncertainty maps make visible.

## Limitations

- Global (single-layer) motion is restricted to the parametric paths offered
  (linear, shake, arc). Layered paths are constant-velocity per layer; the
  velocity re-estimation is a coarse protected grid scan, not a free optical flow.
- The number of motion layers is capped (`MAX_LAYERS = 3`) and each layer adds a
  full latent plus kernel, so degrees of freedom are deliberately limited. Weakly
  observed layers are reported as uncertain rather than split further.
- Data-driven coverage estimation relies on motion-compensated frame differences.
  Under a long shutter the background's own blur can nearly match the foreground
  signal, so blind masks on fast opposed-motion clips are imperfect; the forward
  residual and uncertainty maps expose this. With correct (oracle) coverage the
  same solver closes the loop almost exactly, isolating segmentation — not the
  inversion — as the limiting factor on those clips.
- The motion parameters are user-stated assumptions (or residual-scan refinements
  of them); blind registration only provides a starting point and is biased toward
  zero blur.
- The frozen-coverage boundary approximation is FFT-friendly but differs from the
  exact time-sampled composite at moving edges; the error is localised to layer
  boundaries by construction and is demonstrated in the regression tests.
- Low-texture regions and severe blur can have no unique solution; the support and
  uncertainty maps expose this instead of inventing detail.
- The synthetic scene and forward model are discrete and shared between generation
  and inversion, so the clean-case forward residual is exactly zero. Real sensor
  data would add calibration error that this prototype does not model.
